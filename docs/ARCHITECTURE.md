# Architecture

Audit written 2026-11-12 against `PLAN.md` (the Phase 0–3 build plan), at manifest version 0.12.0 on `main`
(0.12.1 changes are on `main` but unreleased). Facts below were read from the code; items marked *(unverified)*
were not checked.

## 1. What ships

One extension folder, `extension/`, for Chrome, Edge and Firefox. There is no bundler and no runtime
dependency: the files in `extension/` are the files in the store package. That is a public promise
("no build step", stated in the listings, README and guide 4, in 50 languages), so Vite is **not** adopted.

| Store | Package | How it differs |
|---|---|---|
| Chrome | `dist/imgkeep-<v>.zip` | the folder as it is |
| Edge | `dist/imgkeep-edge-<v>.zip` (`scripts/build-edge.mjs`) | shorter store name, otherwise identical |
| Firefox | `dist/imgkeep-firefox-<v>.zip` (`scripts/build-firefox.mjs`) | manifest only: background page instead of service worker, no `offscreen`, gecko id `imgkeep@imgkeep.app`, min 140, optional `data_collection_permissions` |

Browser differences live in `extension/lib/browser.js` (`IS_FIREFOX`, `FOLDERS`, `countsAllowed`, `isStoreSite`).
That file is the existing "platform adapter"; it is small and feature-flag style, not a wrapper around every API.

## 3. How a save works

1. `contextMenus` click → `background.js` `menuClicked` builds a job from `info.srcUrl` (or, on covered sites, from
   Find image here, see below).
2. Chrome/Edge: `background.js` opens the offscreen document and sends it the job. Firefox: `offscreen.js` is
   imported into the background page and called directly (`runInPage`).
3. `offscreen.js` `fetchImage(url)`: `fetch` with `credentials: "include"`, then `"omit"`. Non-OK or empty
   responses become a `JobError` and **no file is written**. A site that blocks cross-site reads triggers the
   "Allow Imgkeep to get images from this site?" question, which requests the optional host permission for that
   one site, then retries.
4. `lib/convert.js` decodes (canvas / ImageDecoder), applies max width, background colour for JPG/BMP, and encodes
   PNG, JPG, WebP, GIF, PDF, ICO, BMP or AVIF. Output bytes are checked before saving.
5. `chrome.downloads.download` into Downloads (with subfolder and `conflictAction: "uniquify"`), a chosen
   folder (File System Access, not Firefox) or Save As.
6. Success/failure counts are queued for the daily summary; the rating ask is evaluated after quick saves.

Other flows: **Copy as PNG** (focused `copy.html` window writes the clipboard, no permission), **Get colour palette**
(`palette.html`, k-means in Lab), **More options** (`editor.html` live preview), **Find image here** (optional
`activeTab` + `scripting` inject `find-image.js` once, on sites in `COVERED_SITES`), **blob: images**
(`read-blob.js` injected once, after the user allows the site).

Animation: GIF sources are kept as they are; animated WebP/AVIF/APNG saved as GIF are re-encoded frame by frame
(caps in `GIF_LIMITS`). Saving an animated source to a static format gives the first frame. *(Animated WebP/APNG
output and a "keep motion" hint are not built.)*

## 4. Permissions and network

Source of truth: `PERMISSIONS.md` (test-enforced against the manifest) and `tests/static-check.mjs`.

- Required: `contextMenus`, `downloads`, `storage`, `offscreen` (Firefox: no `offscreen`).
- Optional: `activeTab`, `scripting`, and per-site `http(s)://*/*` host access.
- No `host_permissions`, no content scripts, no `tabs`, no `clipboardWrite`.
- CSP: `script-src 'self' 'wasm-unsafe-eval'; object-src 'self'`, pinned by the static check.
- Network: only (a) the image the user clicked, from `offscreen.js`, and (b) one anonymous daily summary to
  `https://eu.i.posthog.com/i/v0/e/` from `lib/telemetry.js` (on by default, off in Options; on Firefox only with
  the browser's opt-in). The website separately sends two anonymous counts (`site/count.js`).
  The static check fails on any other `fetch(` or URL.

## 5. Build, release, tests, CI

- Release flow: `release/x.y.z` branch → `npm test` → `sh scripts/package.sh` (zips `extension/` with `zip -X`;
  not yet verified deterministic) → tag → push → CI → store upload scripts (`cws-publish.mjs`, `edge-publish.sh`,
  `amo-publish.mjs`). `scripts/release.mjs` orchestrates. Submitting to a store always waits for Yaron's OK.
- Tests: Playwright, one worker, shared Chromium profile. About 190 test cases (186 at the last site/i18n run): extension (Chromium), Firefox
  (real Firefox over BiDi), site, converter, palette tool, i18n, translations, telemetry, blob, find, settings.
  Fixtures in `tests/fixtures/` (png/jpg/webp/avif/svg, animated gif/webp, many-frames, `covered/` sites).
  `tests/servers.mjs` is a static file server with an optional CORS header.
- CI: `.github/workflows/test.yml` (Linux + Windows, `npm test`), `pages.yml` (site deploy). No lint, no
  per-browser build matrix, no tag-time release artefact.

## 7. Decisions recorded 2026-11-12

- **A. Referer rule.** A `declarativeNetRequest` session rule setting `Referer` to the page URL is allowed as the
  last step before the screenshot fallback, only after the simple steps fail, and only as an **optional**
  permission asked at first failure ("This site blocks direct downloads. Allow Imgkeep to retry the way the page
  does?"). Verified in Chromium on 2026-11-12: `declarativeNetRequestWithHostAccess` is accepted in
  `optional_permissions` with no manifest error or install warning, and a session `modifyHeaders` rule changed the
  `Referer` a server received. Rule is added per request and removed right after. **Firefox is unverified**
  (needs its own test: DNR `modifyHeaders`, or `webRequest`, as optional). Host access is still per site, so the
  existing per-site question stays the gate. Needs a `PERMISSIONS.md` row and a privacy line before shipping.
- **B. CDN rules (1.2)** do not need the Referer rule, but they request another URL than the clicked one (the
  "original" file), possibly on another host (so another per-site question). Fallback to the clicked URL if the
  original fails. Announce-first privacy wording required.
- **C. No content scripts by themselves.** The "nothing runs on pages on its own" promise stays unless a feature
  cannot reach product quality without it. 1.3 and 1.10 are limited to what optional `activeTab` + `scripting`
  allow until a specific gap is shown.
- **D. Rating ask** moves to 5 successful saves/copies as an experiment (one ask, ever). Measured by
  `rating_*` counts.
- **F. Studio = user-held cloud.** Integrations send files from the user's browser to the user's own Drive,
  Dropbox, Notion, Slack or Figma account. No Imgkeep server stores or relays images, and there is no Imgkeep
  account for this. Each integration is opt-in, needs its provider's OAuth (optional `identity` permission,
  tokens kept in local storage on the device), has its own `PERMISSIONS.md` row and privacy section, and is
  announced before it ships. Encrypted sync on our backend (plan 3.1) is not built unless the waitlist shows
  demand. Open questions: OAuth needs each provider's app registration and review; MV3 without a backend means
  PKCE flows only (no client secret); the one-network-request promise changes wording to "the image you clicked,
  and the files you choose to send to your own account".
- **E. Telemetry.** PostHog stays as is (opt-out in Chrome/Edge, opt-in in Firefox). Pro will add its own layer
  (backend, accounts, pricing), announced first, per `Output/Decisions/Imgkeep Telemetry.md`.
